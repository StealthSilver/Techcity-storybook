Brand in one paragraph

TechCity Skills looks light and airy: white grounds, generous space and a fine guide-line layout that shows the structure rather than hiding it. It is quietly confident — one navy accent, plain words and real numbers carry the message instead of effects. Everything is practical rather than flashy: if a detail does not help someone understand a program or take the next step, it does not ship.

Design principles

Five rules. When two choices both look fine, these decide.

01
Content first.

Layout serves the words and figures. Start with the copy, then draw the box around it.

02
One accent per view.

Navy is the accent; amber highlights one thing at most. If everything is highlighted, nothing is.

03
Light grounds, hairline structure.

White and near-white surfaces divided by 1px --line rules. Structure is drawn, not filled.

04
Motion with a cause.

Things move to show a response — a hover, an opened menu, a scene playing. Never decoration on a loop.

05
Real words only where they matter.

Real copy for headlines, buttons and figures. Mark everything else clearly as draft until it is real.

—
In doubt?

Remove something. The quieter version is usually the TechCity version.

Naming conventions

Every component CSS file uses a short prefix so classes never collide. Shared primitives use pp-; each area has its own.

PrefixScopeExamples
pp-Shared page primitives used site-widepp-grid, pp-tiles, pp-stats, pp-tint
pd-Product pages To confirmpd-hero, pd-scene
cr-Careers To confirmcr-ribbon, cr-roles
tm-Team To confirmtm-portrait, tm-grid
pg-Programs To confirmpg-card, pg-syllabus
nr-Newsroom To confirmnr-list, nr-article
  • Pattern: prefix-block, then prefix-block__part and is-state modifiers.
  • Never style another area’s prefix. If two areas need it, promote it to pp-.
  • Components are PascalCase (ProgramCard.tsx) with a matching CSS file.

How to add a new page

  1. Create the route.

    Add app/<route>/page.tsx and export metadata with a sentence-case title and description.

  2. Put the content in lib/ first.

    Add or extend a data file. The page reads from data; it does not hard-code copy, figures or image paths.

  3. Compose from page-blocks.

    Start with the run-in heading block, then pick ruled grids or card grids. Reuse before you build.

  4. Only then build what is missing.

    New block = new .tsx + .css pair with the area prefix. Use tokens from globals.css only — no new hex values.

  5. Check grounds and accents.

    No two strong grounds next to each other. One accent per view.

  6. Check three widths.

    Below 640, 768 and 1024. Gutters should switch from 20px to 40px at 640.

  7. Add it to navigation and the sitemap,

    then run lint and a production build before opening a pull request.

Using the stageshow kit for product scenes

Product scenes — the animated windows showing a product at work — are built with the stageshow kit, never by hand. Its skill explains scene structure, timing and how to swap in product screens.

The run-in headline — the site’s signature

A headline is two sentences in one line of type: a dark lead sentence that states the point and ends with a full stop, followed by a muted continuation that explains it. Same size, same weight — only colour changes.

Skills employers hire for. Programs designed with industry partners, taught by people who do the work.
lead · --text · 500continuation · --muted · 500same size, one element
Learn on campus. Our programs run inside partner colleges, alongside your degree.
On navy. The lead goes white; the continuation goes to 66–72% white.
<h2 class="pp-runin">
  <strong>Skills employers hire for.</strong>
  <span>Programs designed with industry partners.</span>
</h2>
/* .pp-runin strong { color: var(--text) }  .pp-runin span { color: var(--muted) } */
Do

Lead is a complete thought with a full stop.

Continuation adds the how or why.

Sentence case throughout.

Don’t

Bold the lead or change its size.

Break the two parts onto separate lines on purpose.

Use a colon, dash or question mark instead of the full stop.

04 Iconography and imagery

Fine lines, real things. Icons, arrows and logos.

Icons

Pikaicons only. Stroke style, 1.5px stroke, round caps and joins. Icons take the colour of the text next to them (currentColor) — usually --soft, or --accent inside a link or button.

  • Sizes: 16 (inline with small text), 18 (buttons, nav), 20 (card headers). Nothing else.
  • No filled icons, no icons in coloured squares or circles.
  • Never colour an icon amber.
# find an icon
npx pikaicons search calendar
# add it to the project
npx pikaicons add calendar

@/components/icons is the older set. Leave existing uses alone, but don’t add new icons there — replace with Pikaicons when you touch that component.
